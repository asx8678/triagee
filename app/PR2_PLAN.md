## Scope and evidence

Opening requires both owner and environment as explicit nonblank scalar strings, raw valid UTF-8, no NUL/C0/DEL, <=120 characters after trimming. Nil/blank/All-as-absence is NOT a review scope. Validate before database access. Reuse `Inventory.fetch_finding(finding_id, owner: owner, environment: environment)` for the active AND-scope gate. Do not export or refactor Inventory.normalize merely to save a few lines. Malformed IDs/types must return a controlled error before a bigint cast/query. Preserve actual unknown namespace/context values; never invent workload evidence or imply a scoped manual assessment authorizes a global disposition.

Snapshot `payload` is plain string-keyed JSON-compatible data with this stable shape:

- `schema_version`: 1
- `source`: `synthetic_local_inventory`
- `scope`: owner/environment
- `finding`: id, image_id, cve, package_name, package_version, severity, fix, url, description, suppressed, first_seen, last_seen, resolved_at, reopen_count
- `image`: id, digest, repository, tag, description
- `placements`: deterministically sorted scoped records with id, owner, namespace, environment, active, first_seen, last_seen
- `events`: deterministically sorted finding lifecycle records with id, event, occurred_at, note
- `coverage`: explicit local/synthetic/unknown-production-coverage warning, not a completeness assertion

Render these captured facts, not a live Inventory preload masquerading as frozen evidence. Timestamps in payload are ISO8601 or nil. Do not include mutable ORM inserted_at/updated_at or capture time in the content hash. Do retain real source first_seen/last_seen and lifecycle timestamps. Hash canonical structured content deterministically (e.g. deterministic Erlang term serialization of the normalized plain-data map plus a version marker, or genuinely recursive canonical JSON); NOT unchecked string concatenation or arbitrary Jason map iteration order. Sorting must make query/map insertion order irrelevant. captured_at is separate snapshot metadata. Equal content hash is not proof of producer trust or production freshness.

Existing-case history stays readable if its scoped placement later retires. New case creation and review submission fail closed if no active scoped placement remains. Refresh of such a case returns source_out_of_scope without taking an unscoped snapshot. A resolved finding with still-active placements can be captured/reviewed, but resolution remains a scanner observation, not verified mitigation. These are chosen local defaults, not reasons to stop for product clarification.

## Shared public API (implement these exact names/results)

All below are in `Triage.Cases`. Integer URL values may be parsed at boundaries, but must be validated against positive PostgreSQL bigint bounds before querying. Errors are controlled, including non-map/list/nil input. No reads create records.

1. `open_case(finding_id, opts)` where opts is `[owner: ..., environment: ...]`:
   - `{:ok, %{case: review_case, snapshot: snapshot, created?: boolean}}`
   - `{:error, :invalid_scope | :out_of_scope | :not_found | :invalid_request}` (or a validation changeset where appropriate).
   Explicit action only. Concurrent/repeated opens converge to one case, initial snapshot and opening event. Opening an existing case never refreshes its evidence or erases review history.
2. `get_case(case_id)`:
   - `{:ok, %{case: review_case, snapshot: current_snapshot, snapshots: snapshots, reviews: reviews, events: events, evidence_status: status}}`
   - `{:error, :not_found | :invalid_request}`.
   `status` is `:current | :changed | :source_out_of_scope | :source_missing`, derived read-only against current scoped local inventory. Current snapshot is explicit; historical snapshots/reviews/events are deterministically ordered and accessible for the timeline. No DB writes from GET/mount/handle_params.
3. `change_review(attrs \\ %{})` returns a validation changeset for the four manual fields; use normal Ecto/Phoenix form handling. Rationale required, nonblank, <=2000 characters, valid UTF-8 and NUL-free. Ordinary newline/tab in a textarea is allowed. Applicability: affected/not_affected_with_evidence/unknown. Priority: expedited_review/normal_review/insufficient_context. Next action: investigation/dependency_update/base_image_update/rebuild_deploy/mitigation_review/exception_proposal. No extra accepted/rejected outcome field in this slice: avoid confusing an assessment with external approval.
4. `submit_review(case_id, expected_revision, expected_snapshot_id, idempotency_token, attrs)`:
   - `{:ok, %{case: updated_case, review: review, replayed?: boolean}}`
   - `{:error, :conflict | :evidence_stale | :source_out_of_scope | :not_found | :invalid_request | :token_reuse}` or `{:error, changeset}`.
   `attrs` only carries manual fields. Metadata is validated separately; server ignores/rejects forged actor/case/scope/hash fields. UUID tokens generated with `Ecto.UUID.generate/0`, stored per case, and retained in a real form submission so an already-queued double-click/retry cannot accidentally use a newly regenerated server token.
5. `refresh_evidence(case_id, expected_revision, expected_snapshot_id)`:
   - `{:ok, %{case: case, snapshot: snapshot, changed?: boolean}}`
   - controlled `{:error, :conflict | :source_out_of_scope | :not_found | :invalid_request}`.
   Explicit user action/confirmation only; unchanged content causes no new snapshot/event/revision. Changed content appends a snapshot and event and increments revision atomically; never modifies older evidence/reviews. Historical reviews are labelled as needing revalidation when tied to older evidence; source changes also show an evidence-stale notice before recapture.

Submit ordering inside one row-locked transaction: validate request shape; find case; inspect existing token first. Exact same normalized manual payload AND original expected snapshot/revision returns the original review without any writes even after later revisions. Same token with different content/metadata returns token_reuse, NEVER silently replays. Then check expected revision and same-case current snapshot, then recompute current source fingerprint/active scope. Conflict/stale/out-of-scope returns with no writes. Finally insert review, increment revision and append event atomically. Unique indexes back up race handling. A forced final-event failure must roll back the review and revision too. No modifications to findings/images/placements/lifecycle/suppression.
